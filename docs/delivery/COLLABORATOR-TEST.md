# Mouse Tracker Tabajara: collaborator test

This Windows release is for collaborator testing. Tracking coverage, synthetic QA and descriptive reports do not establish real study accuracy or biological conclusions. No additional videos are required from the original user before delivery. Please test locally with recordings you are authorized to use; feedback can follow later.

1. Extract the complete portable ZIP into a new version-named folder. Keep its manifest/notices. Launch `desktop\MouseTrackerTabajara.exe`; do not move the EXE alone. For a chosen study file, launch `desktop\MouseTrackerTabajara.exe --study "D:\TabajaraStudies\Luciana\working.tabajara"`. Keep the previous release folder. Recognized Microsoft Cloud Files folders such as OneDrive are supported for local project New/Save/Open; cloud synchronization and conflict recovery across machines have not been certified.
2. Choose New project for a new `.tabajara` working file, or Open project for a saved `.tabajara`/legacy `.db`/`.morrisdb`. The database autosaves completed analyses and metadata. For example, create `D:\TabajaraStudies\Luciana\working.tabajara`, then save a checkpoint as `D:\TabajaraStudies\Luciana\checkpoints\after-10.tabajara`. Save processed project writes a new point-in-time SQLite snapshot without overwriting an existing file; it does not move videos or switch the currently open workspace. Close processing and review/report windows before these actions. First smoke check: the native workspace should open and resize to1050×700 with Add videos, Analyze all, Cancel and settings/review controls accessible. Release QA uses synthetic recordings; if a synthetic study is supplied, open a COPY and use it first. Opening the empty workspace is sufficient to begin testing when no sample study is supplied. An actual clean collaborator machine has not been independently certified.
3. Add videos imports local paths; it does not upload recordings. Keep original files unchanged and available at their recorded paths. The collaborator can import approximately30 local videos together; start with a small selection if preferred. For optional CSV reconciliation, use **Bulk intake** in the top row, then **Preview manifest** and the reviewed apply action; see LUCIANA-PROTOCOL.md below for a five-column example. Manual Add videos and table editing remain available. Set Animal, ID confirmed, Group, Trial type, Day and Trial in the recording table; keep the same animal ID across its repeated trials and confirm the intended study plan/design before group comparisons. Check displayed source dimensions and exact frame navigation before analysis. A recording label is not proof of a confirmed animal or treatment assignment: keep identities provisional until checked.
4. For a dark mouse on a lighter background, leave Detect dark animals selected; verify the Detection mask against actual pixels. Set pool geometry and check Pool boundary confirmed only after inspection. Set platform geometry when applicable. Adjust threshold/area/step settings for your source and Save settings. A detector profile does not establish measured physical calibration. Do not enter invented centimeters or infer water-plane calibration from normalized coordinates.
5. Use Analyze selected for an initial recording, then Analyze all for the collection. Monitor the queue and Cancel if needed. To pause work, Cancel and wait for the queue to settle, then Save processed project under a new name. Close the app/computer and later Open project on that snapshot. Analyze all reuses complete matching source/settings runs and processes remaining clips. Resume is at the video boundary: an interrupted clip may restart from its beginning; completed clips and raw run IDs are retained when source bytes/settings still match. The snapshot includes metadata, plan, corrections and operational attempt history; original videos stay external and must remain available. For example, reopening after-10.tabajara can reuse the ten completed clips and analyze the remaining twenty. Completed evidence and interrupted/failed items need separate review; a cancelled queue is not a completed study. Changed settings invalidate relevant prior review/results rather than rewriting raw runs.
6. Inspect positions, unknown gaps and suspicious jumps against exact original frames. Make corrections with an explanation. Confirm tracking review only after checking the relevant evidence. For trial-window endpoints, explicitly confirm the release frame and planned exposure/window; seeking through a video does not change its stored release anchor. Pool/target detection is not an observed mounting or researcher event.
7. Independent reference validation separates Development, Independent validation and Unspecified recordings. Declare session/protocol/roles honestly; do not relabel tuned footage as independent. Choose RawAutomatic versus InspectedCorrected deliberately. Missing, disputed and not-visible references are different states. Sampled frames and recordings are not biological animalN. Saved projects retain complete study metadata; blind review changes the display, not the underlying project. Blind metadata hides software labels; original source pixels may still reveal context. Reveal requires reviewer/reason/audit. Open a selected validation source to reach the annotation tab; acknowledge source-pixel disclosure before viewing. Decoded source previews use lossless transport, and original image pixels are not automatically redacted.
8. Use Whole-study report and the validation comparison views for descriptive results and explicit holds. Read joins/denominators and exclusions alongside conditional errors. Expand Full counts, holds, and provenance for the complete contributors; scroll its details while the result list remains available. Save replayable evidence before export; a stale or legacy held result may require explicit recomputation from frozen material. Do not replace a failed or unavailable result with a zero, or treat pooled development errors as held-out accuracy. For the pt-BR Excel CSV, import UTF-8 with a semicolon delimiter and Portuguese (Brazil) locale so decimal-comma numeric values remain numbers.
9. Before an update, close the desktop and all CLI jobs. Prefer Save processed project before closing: its online SQLite backup incorporates committed WAL pages and embeds operational attempt history, alongside all scientific database tables. Retain that `.tabajara` snapshot, original source recordings and exported evidence/manifests. For a manual closed-project backup, copy the database with any WAL/SHM companions and `.recording-operations.json` operational sidecar together; never naively copy a live database file. Open a separate backup COPY with the new version first. If it fails, close it and use the previous release against another copy of the pre-update backup; do not share one writable database between releases. See PORTABLE.md for version/rollback details.

For feedback, record release version and manifest hash, Windows version, study-copy path (omit identifying details), intended action, exact steps, expected versus observed behavior, and whether it repeats after reopening that copy. Include the displayed hold/error and diagnostics log if appropriate. For numerical issues, state raw/corrected target, role, interval/frame, value and denominator. A synthetic or anonymized reproduction is preferable; do not send private animal/group/source information or video pixels without explicit permission and an agreed channel. Keep originals, failed runs and recovery copies intact.

Next action: launch the extracted build, check the empty/synthetic workspace, then try a small authorized local workflow. Scientific accuracy/design approval and human sign-off remain deferred to collaborator feedback.

For source recordings, use plain-ASCII folder/file names for this pilot: current intake QA reports accented source paths as `undecodable-video` despite valid UTF-8 manifest parsing/hashing. See LUCIANA-PROTOCOL.md. This does not mean Unicode application extraction folders are unsupported.
